# Shop Backend

Проект представляет собой серверную часть интернет-магазина, разработанную на Python с использованием современных инструментов автоматизации и проверки качества кода.

## 🛠️ Стек технологий
* **Язык**: Python 3.10+
* **Менеджер пакетов**: Poetry
* **Форматирование и стиль**: Black, isort, Flake8
* **Статический анализ типов**: Mypy
* **Тестирование**: Pytest, pytest-cov

## 📦 Структура проекта
* `src/` — исходный код приложения:
  * `product.py` — класс `Product` с инкапсулированной ценой, валидацией.
  * `category.py` — класс `Category` с приватным списком товаров.
  * `utils.py` — утилита для подгрузки данных из внешнего JSON-файла.
  * `category_iterator.py` — вспомогательный класс-итератор для перебора товаров в цикле `for`.
  * `lawn_grass.py` — класс-наследник `LawnGrass` со специальными свойствами.
  * `smartphone.py` — класс-наследник `Smartphone` со специальными свойствами.
  * `order.py` — класс `Order` (Заказ) и абстрактный класс `BaseGroup`.
  * `print_mixin.py` — миксин для автоматического логирования создания объектов.
* `tests/` — раздельные модульные тесты для проверки бизнес-логики...
* `main.py` — проверочный скрипт для верификации работы моделей...
* `products.json` — файл с исходными данными для подгрузки товаров.
* `exceptions.py` — пользовательские классы исключений для обработки ошибок валидации данных.


## 🚀 Установка и запуск

1. Клонируйте репозиторий и перейдите в папку проекта:
```bash
git clone <ссылка_на_ваш_репозиторий>
cd shop_backend
```

2. Установите зависимости разработки через Poetry:
```bash
poetry install
```

3. Запустите комплексную автоматическую проверку кода (линтеры, форматирование, статический анализ и тесты с генерацией отчёта):
```bash
poetry run poe fix
```

4. Для проверки базовой работоспособности и чтения JSON запустите скрипт:
```bash
poetry run python main.py
```

## ✨ Абстракция и миксины
1. **Абстрактные классы**: Создан базовый абстрактный класс `BaseProduct` для продуктов с обязательным фабричным методом `new_product`. Также создан абстрактный класс `BaseGroup` для группирующих сущностей (`Category` и `Order`).
2. **Множественное наследование и логирование**: Класс `Product` переведён на множественное наследование и теперь включает в себя `PrintMixin`, который автоматически выводит в консоль информацию о каждом созданном товаре и его свойствах.


## ⚠️ Обработка исключений
1. **Пользовательские ошибки**: Создан собственный класс исключения `ZeroQuantityProductError`, наследующийся от `ValueError`. Он блокирует создание или добавление продуктов с нулевым или отрицательным количеством.
2. **Надёжные вычисления**: Метод `middle_price` в классе `Category` защищён конструкцией `try-except` от ошибки деления на ноль (`ZeroDivisionError`). Если в категории нет товаров, метод безопасно возвращает `0.0`.
3. **Комплексная валидация**: В методы добавления товаров для `Category` и `Order` внедрена полная конструкция `try-except-else-finally`. В случае успеха выводится сообщение «Товар добавлен.», а блок `finally` гарантирует вывод строки «Обработка добавления товара завершена.» при любом исходе.


## 🔒 Реализованные механизмы инкапсуляции
1. **Скрытие данных (Приватность)**: Список товаров категории (`__products`) и цена товара (`__price`) защищены двойным нижним подчёркиванием. Доступ к ним извне возможен только через строго определённые интерфейсы.
2. **Безопасное управление ценой**: Сеттер цены блокирует установку нулевой или отрицательной стоимости. 
3. **Интерактивное подтверждение**: При попытке снизить цену товара система запрашивает ручное подтверждение у пользователя через консольный ввод (`y/n`).
4. **Умное слияние дубликатов**: Метод `Product.new_product()` автоматически находит товары-дубликаты в магазине, объединяет их остатки на складе и выбирает наибольшую цену из двух.


## ✨ Перегрузка операторов и магические методы
1. **Строковое отображение (`__str__`)**: Объекты классов продуктов и категорий теперь поддерживают красивый вывод через `print()` [INDEX].
   * Продукт выводится в формате: `Название продукта, X руб. Остаток: X шт.`
   * Категория выводится в формате: `Название категории, количество продуктов: X шт.` (считается сумма всех единиц товаров на складе) [INDEX].
2. **Сложение товаров (`__add__`)**: Реализована возможность складывать объекты продуктов через оператор `+`. Результатом сложения является полная стоимость всех единиц этих двух товаров на складе [INDEX].
3. **Итерация по категориям (`__iter__`, `__next__`)**: Благодаря классу `CategoryIterator` объекты категорий можно перебирать в обычном цикле `for` для построчного вывода продуктов [INDEX].

## 🧬 Наследование и полиморфизм
1. **Классы-наследники**: Созданы специализированные модели `Smartphone` и `LawnGrass`, которые наследуют общие свойства от базового класса `Product` через механизм `super().__init__()`.
2. **Строгая валидация при сложении**: Магический метод `__add__` в базовом классе доработан с помощью функции `type()`. Попытка сложить продукты разных классов теперь вызывает исключение `TypeError`.
3. **Контроль типов в категориях**: Метод `add_product` класса `Category` защищён проверкой `isinstance()`. Добавление любых объектов, не являющихся экземплярами класса `Product` или его наследников, строго заблокировано.
